# Phase 04 — 全尺寸度量的成本與裝置歸屬

## 為什麼記這一筆

phase-04 preflight 依 phase-02／03 的數字推估單張端到端約 21–22 秒。第一次真實執行量到 **85.5 秒**，是推估的四倍。追查後發現兩件影響後續階段的事，兩件都不是「數字不好看」，而是**成本模型與報告正確性**的問題。

## 發現一：全尺寸 SSIM 是成本與記憶體的主導者

phase-02 的性質檢查都在 48×64 到 160×128 的小圖上做，成本與真實尺寸完全不同量級。在 4056×3040 上逐項實測（沙箱 CPU）：

| 項目 | 耗時 | 備註 |
|---|---|---|
| 載入一張 4056×3040 為度量張量 | 0.40 s | |
| PSNR | 0.14 s | |
| **SSIM（原實作）** | **21.34 s** | 主導項 |
| LPIPS | 3.09 s | phase-02 的 4.74 s 含模型載入 |

每張圖要各算兩次（SR 線與 bicubic 線），所以光 SSIM 就佔約 43 秒。

**記憶體更嚴重。** 在各自獨立的程序中量測同一組真實輸入：

| SSIM 形式 | 耗時 | 程序峰值 RSS | 值 |
|---|---|---|---|
| 三通道一次、11×11 kernel（原） | 21.82 s | **15423 MiB** | `0.599408548507597` |
| 逐通道、11×11 kernel | 21.26 s | 13269 MiB | `0.5994085485075983` |
| **逐通道、可分離（現行）** | **4.33 s** | **3355 MiB** | `0.5994085485075943` |

單一次 SSIM 呼叫的峰值 RSS 15.4 GiB，在筆電上是真實的 OOM 風險，而**交付執行就發生在使用者的機器上**。

### 採取的修正與其正當性

改為**逐通道 + 可分離高斯**（commit `264c6b4`）。

- **定義未變。** 11×11 window 本來就是以正規化一維高斯的外積建構（`_gaussian_line` 即該一維核）。分成兩次一維卷積是同一個卷積，只有加總順序不同。
- **實測差距 `2.665e-15`**（float64 捨入層級）。
- **守門證據仍在且仍通過：** phase-02 建立的 naive 逐視窗交叉核對，用的是**二維 kernel、明確走訪每個視窗**的獨立實作，容差 1e-9，改動後依然通過。這正是當初寫它的理由。
- **授權依據：** `AGENTS.md`「為避免記憶體不足、相容性問題或無法完成處理而必要的調整，屬於讓流程可運行的工作」。這不是畫質優化，也不是為了改善分數——分數在 1e-15 的層級沒有動。

### 對後續階段的影響（沙箱 CPU 實測）

| | 修正前 | 修正後 |
|---|---|---|
| 單張端到端 | 85.5 s | **30.3 s** |
| 程序峰值 RSS | ~15.4 GiB | **4287 MiB** |
| 十分鐘授權內的張數 | 約 7 張 | **約 20 張** |

phase-04 的預設 `--limit 5` 因此對應約 150 秒，寬鬆落在授權內。**這些仍是沙箱 CPU 數字**；交付裝置的數字由「待 GPU 補測」補上。

## 發現二：PSNR／SSIM 根本不跑在 SR 的裝置上

度量的輸入來自 Pillow 解碼（`load_metric_tensor`），是 CPU 張量，`psnr()` 與 `ssim()` 就地計算，**從不搬到 GPU**。只有 LPIPS 會 `.to(device)`。

原本的報告標頭只有一欄「度量 device」，填的是 SR 線的裝置。在沙箱 CPU 執行時碰巧正確；**在使用者的 GPU 執行時，那一欄會把四個（PSNR／SSIM × 兩條線）實際在 CPU 算出來的數字標成 GPU**。

修正（commit `63d1e2c`）：標頭拆成「PSNR／SSIM device」與「LPIPS device」，並改寫「跨批次可比性」——受裝置影響的只有 SR 線與 LPIPS，PSNR／SSIM 恆為 CPU float64，**跨裝置可精確重現**。

這也順帶降低了 GPU 路徑的 VRAM 風險：float64 的全尺寸 SSIM 若真的搬上 12227 MiB 的卡會直接放不下，而它從來不會被搬上去。「待 GPU 補測」第 1 項（LPIPS 全尺寸 VRAM）不受影響，仍需實測。

## 與固定約定的關係

`GOALS.md`「固定的度量約定」第 6 條要求「單次執行內，SR 線與三個度量所用的裝置固定，並寫進報告標頭」。現行行為滿足它：三者的裝置各自固定（SR 與 LPIPS 跟隨可用裝置，PSNR／SSIM 恆為 CPU），且全部寫進標頭。該條原文並未要求三者必須是同一個裝置，同一節也已載明「bicubic 線恆為 Pillow 的 CPU 實作，不受裝置選擇影響」。**未修改 `GOALS.md`。**
